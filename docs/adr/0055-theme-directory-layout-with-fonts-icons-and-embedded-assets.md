# 55. Theme directory layout with fonts, icons, and embedded assets

Date: 2026-09-11

## Status

Accepted

Amended 2026-09-11: the built-in theme's faces are Fraunces (titles),
Literata (note bodies), DM Sans (chrome), and DM Mono (data), and its
palette is warm paper with amber-brown ink by day and warm black with
gold at night, chosen from six proposed looks (research log, Q70 and
Q71). The layout, the icon mechanism, and the embedding are unchanged;
the font files under `fonts/` are those four families, all under the SIL
Open Font License.

Extends [ADR 0048](0048-site-themes-as-stylesheets-and-assets.md), which
it amends, and the embedding of built output in
[ADR 0051](0051-browser-side-code-in-typescript-with-committed-build.md).
The markup the icons appear in is
[ADR 0050](0050-page-templates-with-minijinja.md) and
[ADR 0054](0054-site-navigation-and-url-scheme.md).

## Context

The built-in site theme uses the three IBM Plex families and Lucide
icons. The site must work when opened from disk, so both have to ship
inside the export: a font is a file the stylesheet references, but an
icon drawn from a separate file does not work over `file://` in Chrome,
which refuses a `<use>` of another SVG file and a CSS mask image from
another file as cross-origin. Icons inlined into the stylesheet as data
URIs work everywhere but duplicate the icon source. The user asked for
one directory layout shared by the built-in theme and a vault's themes,
with fonts and icons as plain files rather than manifests, written with
web development knowledge alone; for the built-in theme's files to be
embedded automatically and compressed; and for a build dependency that
does not enter the binary.

## Decision

### Layout

A theme is a directory with this shape, the built-in theme under
`src/site/theme/` and a vault theme under `.ntropy/themes/site/<name>/`
alike:

    style.css        the entry point, required
    icons/*.svg      one icon per file
    fonts/*          files the stylesheet references with url(fonts/...)
    anything else    copied under the site's assets/ as it is

There is no manifest. Every file is copied under `assets/`, so the
stylesheet references fonts and other files relative to itself.

### Icons

At export, every `<name>.svg` under `icons/` becomes one
`<symbol id="icon-<name>">` of a hidden inline `<svg>` that every page
and every `render --to html` document carries. The symbol keeps the
file's root attributes except the namespace, `width`, `height`, `class`,
and `id`. The markup shows an icon as
`<svg class="icon"><use href="#icon-<name>"/></svg>`. A vault theme's
icons are layered by name over the built-in ones: a file with a built-in
name replaces that icon, any other name adds one, and a theme without an
`icons/` directory keeps every built-in icon. A file under `icons/` that
has no `<svg>` root fails the export naming the file.

### Fonts

The stylesheet declares its faces with `@font-face` over `fonts/`. The
standalone `render --to html` document inlines the stylesheet and has no
`fonts/` beside it; its faces fall back to the system stacks the
stylesheet names.

### Sources

The built-in theme's font files (IBM Plex Sans, Serif, and Mono under
the SIL Open Font License 1.1) and icon files (Lucide under the ISC
license) are committed under `src/site/theme/fonts/` and
`src/site/theme/icons/` with their license files, and updated by copying
files. The frontend build does not copy them and depends on neither
package.

### Embedding

A build script embeds every file under `src/site/theme/` and
`src/site/dist/` into the binary as a generated table, so a file added to
either directory ships without being listed. Each file is zstd-compressed
with the `ruzstd` crate's encoder and stored compressed when that is
smaller, raw otherwise; the same crate inflates at export. `ruzstd` is a
build dependency for the encoder and a regular dependency for the
decoder; no C library takes part.

### Rejected alternatives

- **Icons as CSS mask images**, from separate files (refused over
  `file://`) or as data URIs generated into a stylesheet (a second copy
  of every icon).
- **The sprite generated by the frontend build**, from a name list and
  the Lucide package; a vault theme could not have been treated the same
  way.
- **A theme's `icons/` as the whole set**, with nothing inherited.
- **Fonts and icons copied from npm packages by the frontend build**,
  with manifests naming the files.
- **Fonts inlined into the standalone document** as data URIs.
- **Hand-listed embedded files**, and **compression with the C zstd
  library** in the build script.

## Consequences

- `site theme init` writes a complete, working theme: stylesheet, icons,
  fonts, licenses.
- The icon names the markup references are part of the theme contract
  and are listed in the README.
- A font or icon upgrade of the built-in theme is a file copy.
